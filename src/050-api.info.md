# 050-api.lua

One HTTPS request to a model, and the answer back.

## Functions

### `Api.available(handle) -> true | false, kind, why`
Answered without sending anything. Two absences with two different fixes: no
`config/asking.lua` is somebody who has not set this up; no key is somebody who
has, and left the secret out.

### `Api.send(handle, body) -> decoded | nil, kind, why`
`body` is a Lua table — messages, tools, system. Encoded here so no caller knows
the wire format.

### `Api.FAILURES` — the nine kinds, each with whether retrying helps.

## Why curl

LuaJIT ships no TLS and this project takes no dependencies. But it already
reaches outside itself twice by running a program — `002-cold-hand.lua` runs the
deployment's `mysql`, `003-live-hand.lua` speaks HTTP to SOAP. This is the same
shape, and brings TLS, redirects, timeouts and proxies for free. Linking a TLS
library means a build step and a version of this project that stops running on a
machine where it currently does.

## Where the key is not

**Not on a command line.** Anything in an argument list is visible in `ps` to
every user on the machine. It goes in a header file on the RAM tier, `chmod
600`, handed to curl by path, deleted after. Request and response bodies go the
same way — a tool list plus a conversation is far past any safe argument length,
and a conversation written to disk is one somebody can read.

## The failure that gets missed

**HTTP 200 with an `error` object in the body is not a success.** A caller
checking only the status believes it worked. `003-live-hand.lua` already
documents the same shape for the SOAP console, where a rejected GM command comes
back as 200 with a sentence in it.

`--write-out` puts the status somewhere the body is not, so a 401 carrying JSON
is distinguishable from a 200 carrying the same shape.

## Nine kinds, three worth retrying

`unreachable`, `timed_out`, `rate_limited` and `overloaded` are worth trying
again. `no_key`, `no_config`, `no_curl`, `unauthorized`, `malformed` and
`unreadable` are not — and retrying a 401 is how a wrong key becomes a rate
limit.

A timeout is the awkward one: whether the model did the work anyway is unknowable
from here, which is why nothing in this project applies a change on the strength
of a request it did not see answered.
