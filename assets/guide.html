setting up a model

connecting neuron to something that can think

two roles

neuron talks to two models, and they are told apart by what they are for rather than by where they run.

The game master runs the world. It spawns creatures, moves characters, reads what is out there, and writes the encounters somebody is about to walk into. It has the whole world vocabulary and it is the one worth paying for.

The configuration assistant sets neuron up. It can change where thinking gets sent, read the project’s own source, and write credentials. It can change nothing in the world — not a character, not a creature, not a place — and that is the point rather than a limitation.

The reason for the split is what you need at the moment something is broken. If the API key is wrong, or the endpoint moved, or the account has no credit, the game master cannot help you fix any of it, because fixing it is exactly the thing it cannot do. So the assistant is a life raft, and a life raft that needed the thing that is broken would not be one.

Which is why the assistant is usually the local one. Not a rule — either role can point anywhere — but a model running on your own machine needs no credential and no network, so it is available in precisely the situation the assistant exists for. It is not a general-purpose cheap model, though: its whole vocabulary is neuron’s own settings, and it can do nothing else with it.

pointing them somewhere

Both roles take the same three things: an address, a model name, and — if the service wants one — a key. Anything that speaks either the Anthropic message format or Ollama’s /api/chat will work, and that covers most of what is out there.

serviceaddressa model namekey
Claude https://api.anthropic.com/v1/messages claude-opus-5 yes
OpenAI https://api.openai.com/v1/chat/completions gpt-5 yes
Gemini https://generativelanguage.googleapis.com/v1beta/openai/chat/completions gemini-2.5-pro yes
Ollama http://127.0.0.1:11434/api/chat qwen2.5 no

The key goes in secrets/api.key, and the keys section of the main menu will write it for you. A local model needs none, and the row says so.

neuron speaks two wire formats: Anthropic’s, and Ollama’s. Services that offer an OpenAI-compatible endpoint — which is most of them, Gemini included — are close enough in shape that the Ollama dialect reaches them. If one does not answer, that is the first thing to suspect.

running one yourself

Anything that speaks Ollama’s /api/chat will do. Ollama itself is the shortest path; llama.cpp’s server speaks the same shape and neuron will move to it.

One. Install it, from ollama.com/download or your package manager.

Two. Start it, and leave it running.

ollama serve

Three. Pull a model. Any of them will do something; how well is a gradient rather than a yes or no.

ollama pull qwen2.5
ollama pull llama3.1

how well a model can call a tool

A tool call is properly formatted text, usually shaped like JSON. The model emits characters, and something watching the stream recognises an agreed shape and runs it.

neuron reads both: the field when a server provides one, and the text when it does not. So the question is not whether a model can, it is how reliably. Three tiers, best first.

  • Built-in tool calling. The server has a template for this model and returns calls in their own field. Nothing has to be recognised in prose, so nothing is missed. qwen2.5, qwen3, llama3.1, llama3.2, llama3.3, mistral-nemo, mistral-small, command-r and hermes3 are here.
  • Trained on the shape, without the plumbing. The model has read enough tool calls to write one, and the server hands it back as ordinary text. neuron finds it anyway — balanced-brace scanning, several wrappers handled. Older llama2 builds land here and work, with the occasional retry.
  • No idea what a tool call is. It writes about the tool instead of calling it, or writes something JSON-shaped that means nothing. Every turn is a coin flip.

Anything with embed, bge, rerank or nomic in its name is in none of these tiers: those turn text into vectors and cannot hold a conversation at all. neuron marks them in the model picker so they cannot be chosen by accident.

Size matters more than tier does. A three-billion parameter model that can call tools often writes “I will change the timeout to 15 seconds” instead of changing it — it knows the shape and does not reach for it. Seven or eight billion parameters is where the model starts performing well.

pointing neuron at it

Under services on the main menu, ollama starts and stops like the game servers do, on whatever address it is configured for. Its lamp is how you know it is running, and its log is where it says why it is not.

Under chat, the assistant has two rows. model lists what your server actually has and marks which of them can call tools — that list comes from the server itself, so it cannot name something you have not pulled. address sets where the server is, including the path it answers on, and starting ollama from the menu binds exactly that address, so the two cannot drift.

when it goes wrong

What neuron says, and what to do about it.

not answering

Nothing accepted a connection at that address.

Check that ollama serve is running, and that it is running where neuron is looking. Ollama binds 127.0.0.1:11434 unless OLLAMA_HOST says otherwise, and a server bound to loopback on another machine cannot be reached from this one at all — it needs OLLAMA_HOST=0.0.0.0. Use the address button to point neuron somewhere else.

model ‘x’ not found, try pulling it first

The server is running and does not have that model.

ollama list shows what it does have. Either pull the one you asked for, or press model on the menu and choose from what is actually there — that list comes from the server itself, so it cannot name something that is missing.

the request took too long

The model did not finish inside the timeout.

First generation after a pull is slow: the weights are being read from disk. If it is slow every time, the model does not fit in your graphics card’s memory and is spilling into system memory, which costs an order of magnitude — nvidia-smi or rocm-smi will show it. Either pick a smaller model or a heavier quantisation. The timeout itself is timeout_seconds in the local conversation’s own levers.

Stopped after 12 rounds of tool calls without a final answer

The model kept calling tools and never said anything.

Usually a small model repeating one call. neuron answers a repeat from what it already worked out and stops the moment a whole round is repeats, so this is capped rather than endless — but it means the model is not reading its own results. A larger model does not do it.

it answers in prose about calling a tool

Not an error message; it simply never calls anything.

The model is in the third tier above. It is worth one retry — they are inconsistent rather than incapable — and then worth changing the model.

everything is unreachable

The remote model, the database and the servers are all down.

That is what this model is for. Open a local conversation from the main menu and ask it; it needs none of them.
