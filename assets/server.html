getting AzerothCore running, and getting neuron pointed at it

one — install AzerothCore

Follow the instructions for downloading AzerothCore here.

Come back when you have a built worldserver and authserver, three databases, and the map data extracted.

two — if the dependencies fight you

The most common problem when building AzerothCore from source is the dependencies. Here are some scripts that I made which install the dependencies into a local directory. I would recommend trying your system’s package manager first, though.

if you’re having trouble with the dependencies, try my scripts

Last known good AzerothCore: reading… — the commit this deployment is actually built from. If a fresh clone won’t compile, this is the version that worked for me, and what neuron is built against. Whenever I update my installation, this link updates too.

Read this before running any of them. They work, on the machine they were written on. Somewhere else, four things bite.

They have my paths in them. scripts/boost and scripts/ccache begin DIR="/home/ritz/games/azeroth-core/wow-chat-2026" and take no argument, so that line must be edited. scripts/mysql-install takes a directory as its first argument — and that is its own trap: it claims any first argument that does not start with --, so ./scripts/mysql-install 8.4.0 treats the version as a directory name, silently builds a tree at ./8.4.0/mysql/, and installs whatever the newest release happens to be.

They install no build tools and check for none. A missing compiler, cmake, bison, libzstd, or the OpenSSL and ncurses headers surfaces as a failure deep inside cmake rather than as a sentence — which is the confusing failure these scripts exist to prevent. Install those first.

mysql-install does not stop when a step fails. It sets pipefail but not set -e, so a failed build runs make install, and a failed install goes on to initialise a data directory — possibly against an older binary left over from a previous run. Watch it rather than walking away.

It leaves work behind. It stops for a [y/N] prompt, so it cannot run unattended, and it finishes with the database initialised and no root password. Setting one and creating the three AzerothCore databases are yours. Its closing message also points at scripts/mysql-start, which does not exist — the file is scripts/start-mysql.

three — point neuron at it

neuron contains no game server. It drives one, and it needs a deployment laid out the way this project lays one out — which a stock AzerothCore install is not. Four things have to be there.

whatwhy neuron needs it
.profile One word naming the active profile. Everything downstream is derived from it, and there is no default: without this file neuron refuses to start rather than guess which world it is pointed at.
installed-files-<profile>/etc/ The generated .conf files. Ports come from here, and so does MaxPlayerLevel, which is the single most load-bearing fact in what the game master is told.
mysql/ A MySQL with its socket at mysql/databases/mysql.sock and its client binary in the tree. neuron runs that binary rather than linking a driver.
secrets.conf DB_USER and DB_PASS. It belongs to the deployment, so there is nothing to enter twice.

Databases are named acore_world_<profile>, acore_characters_<profile> and acore_playerbots_<profile>. acore_auth is not suffixed — accounts are shared across every profile on the machine.

The deployment path. At the top of the main menu, the path is a button. It checks for those markers before changing anything, so a wrong path is refused rather than half-accepted.

The game-master password. This one is neuron’s own: a game account with GM rights, whose password goes in secrets/soap.key. It is how neuron types commands at a running world. Without it neuron can still read and write the database, but nothing it does is visible to anybody standing in the game until the server restarts.

touch  secrets/soap.key
chmod 600 secrets/soap.key
printf %s 'the-password' > secrets/soap.key

Create the account in the worldserver console, which the main menu gives you under that service’s log:

account create neuron the-password
account set gmlevel neuron 3 -1

four — play

Start mysql under services, wait for its lamp to go green, then authserver and worldserver. The worldserver takes about half a minute to load its map data before it binds a port; its lamp is amber for that whole time, and stop works throughout.

Then press new conversation (game master) under chat, and ask it for something. It is not a settings panel — it is the thing that runs the world, and the way to find out what it can do is to ask it for what you want.

put four undead around level twelve near goldshire

give me successive encounters of undead, getting harder each time

move my bots to ratchet

Anything that changes the world comes back as a plan, not as a result. Nothing has happened. You read what it proposes and agree to it, and only then does it run — so you can ask for twenty spawns and a teleport and read the whole thing before any of it is true.

Log in with the account you made, and watch it happen.
